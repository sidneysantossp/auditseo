Falhas que impedem indexação adequada, prejudicam credibilidade e comprometem a presença digital do escritório.

🚨
Email de staging exposto em produção
Todas as páginas exibem atendimento@tan-pheasant-154948.hostingersite.com em vez de atendimento@nuneslaw.com.br. Visível nos snippets do Google. Compromete gravemente E-E-A-T (Trustworthiness).
Correções Imediatas (Hoje)
Substituir e-mail de staging por atendimento@nuneslaw.com.br em todo o site (header, footer, contato)
Buscar e substituir tan-pheasant-154948.hostingersite.com no template global do CMS
✅ Como resolver
No painel Hostinger/WordPress → Aparência → Editor de Tema (ou Elementor Global Settings), buscar todas as ocorrências de atendimento@tan-pheasant-154948.hostingersite.com e substituir por atendimento@nuneslaw.com.br. Locais: header template, footer template, página /fale-conosco/, widget de contato, schema JSON-LD (se houver). Após a troca, verificar se o e-mail correto aparece no Google: site:nuneslaw.com.br "atendimento@"
● Crítico
Criar e publicar sitemap.xml e submeter ao Google Search Console
nuneslaw.com.br/sitemap.xml retorna 404. Gerar via Yoast ou manualmente
✅ Como resolver
Instalar Yoast SEO ou RankMath → Ativar funcionalidade de Sitemap XML → URL gerada: https://nuneslaw.com.br/sitemap_index.xml. Em seguida, acessar Google Search Console → Sitemaps → Adicionar https://nuneslaw.com.br/sitemap_index.xml → Enviar. Repetir no Bing Webmaster Tools. Verificar se o robots.txt referencia o sitemap: adicionar ao final do robots.txt a linha Sitemap: https://nuneslaw.com.br/sitemap_index.xml
● Crítico
Redirect 301 da URL duplicada de artigo erro médico
✅ Redirect 301 — De → Para
DE: https://nuneslaw.com.br/artigos/erro-medico-e-seguro-eo-causas-de-negativa/
PARA: https://nuneslaw.com.br/erro-medico-e-seguro-eo-causas-de-negativa/

No .htaccess (Apache) adicionar:
Redirect 301 /artigos/erro-medico-e-seguro-eo-causas-de-negativa/ https://nuneslaw.com.br/erro-medico-e-seguro-eo-causas-de-negativa/

Ou via plugin Redirection (WordPress): Source URL = /artigos/erro-medico-e-seguro-eo-causas-de-negativa/ → Target URL = /erro-medico-e-seguro-eo-causas-de-negativa/ → Type: 301 Permanent.

● Crítico
Adicionar canonical tags em todas as páginas
✅ Como resolver
Yoast/RankMath gera canonicals automaticamente. Verificar se estão presentes no <head> de cada página. Exemplos:
<link rel="canonical" href="https://nuneslaw.com.br/" />
<link rel="canonical" href="https://nuneslaw.com.br/areas-de-atuacao/direito-do-seguro/" />

Sempre usar URL absoluta com https:// e barra final. Para o artigo duplicado de erro médico, a canonical da versão /artigos/ deve apontar para a versão raiz (combinado com o 301).
<link rel="canonical" href="URL-absoluta"> no <head>
● Crítico
Verificar proteção excessiva do Cloudflare que bloqueia crawlers legítimos
✅ Como resolver
Acessar painel Cloudflare → Security → WAF → Verificar se regras customizadas bloqueiam user-agents de bots de busca. Garantir que Googlebot, Bingbot, GPTBot, Google-Extended e ClaudeBot passem sem challenge. Em Security Level, usar "Medium" (não "I'm Under Attack"). Verificar em Security → Events se há bloqueios de crawlers legítimos.

Avaliar remoção de Content-Signal: ai-train=no
✅ Como resolver
Verificar nos headers HTTP se existe o header Content-Signal: ai-train=no. Se existir, remover no Cloudflare (Transform Rules → Modify Response Header) ou no servidor Apache/Nginx. Para advocacia, a visibilidade em LLMs gera leads qualificados — o benefício de ser citado pelo ChatGPT/Claude/Gemini supera o risco de "treinamento".
Trade-off: proteção de IP vs. visibilidade em IA. Para advocacia, visibilidade é mais valiosa
